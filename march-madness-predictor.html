2026 March Madness Predictor with Logistic Regression

A sports analytics project using machine learning to predict college basketball tournament matchup outcomes based on team performance statistics.

March Madness is the NCAA Division I Men's Basketball Tournament, and predicting game outcomes is a challenging and engaging machine learning problem. This project builds a logistic regression model trained on historical tournament matchup data to forecast the probability that one team will defeat another based on key statistical features. The model evaluates teams using performance metrics and learns the statistical patterns that correlate with tournament success.

At its core, this project demonstrates a complete machine learning pipeline: data preprocessing, feature engineering, model training, and prediction. The key insight is that basketball matchups are not simply about team strength in isolation, but about how two teams match up against each other. By computing difference features—comparing one team's stats against another—the model captures relative advantages and disadvantages that drive game outcomes.

Feature Engineering: The Key Difference Features

The model doesn't evaluate teams in isolation—it compares them directly. For each matchup, I compute seven key difference features that capture how one team stacks up against the other:

Difference Features (Team A minus Team B):
SRS (Rating)
Offensive Rating
Effective FG %
Turnover %
Rebound %
Opp. Def. FG %
Pace

Why this approach works: A team with a high offensive rating is only an advantage if their opponent has a lower one. By computing differences, the model learns relative strengths rather than absolute values. For example, if Duke (strong offense) plays Louisville (weaker defense), the positive difference in offensive rating becomes predictive. The logistic regression then learns which combinations of differences correlate with wins.

The Logistic Regression Model

Logistic regression is chosen for this problem because it outputs calibrated probability estimates—exactly what we need for tournament predictions. The model architecture consists of two stages:

Pipeline Components:
  • StandardScaler: Normalizes all features to have mean 0 and standard deviation 1. This ensures that features with different scales (e.g., pace ranging from 60-80 vs SRS ranging from -30 to +30) contribute equally to the model's decision boundary.
  • LogisticRegression: A linear classifier that learns weights for each feature. Features with positive weights increase the predicted win probability for Team A, while negative weights decrease it. The sigmoid function transforms weighted sums into probabilities between 0 and 1.

Model Configuration:

  • penalty="l2" — Regularization to prevent overfitting
  • solver="lbfgs" — Optimization algorithm for combining different feature scales
  • max_iter=1000 — Maximum iterations to find optimal weights

Data Preprocessing & Real-World Challenges

Real tournament data is messy. Team names vary across sources: is it "Brigham Young" or "BYU"? Is it "UConn" or "Connecticut"? This project includes a comprehensive name-mapping dictionary to standardize all team references before processing:

Name Standardization Examples:
  • BYU → Brigham Young
  • Uconn → Connecticut
  • VCU → Virginia Commonwealth
  • St Johns → Saint John's (NY)
  • Penn → Pennsylvania

After standardization, the model filters to only matchups where both teams have complete statistical profiles in the dataset. Games with missing team data are excluded, preserving prediction integrity. This ensures every prediction is grounded in reliable historical data rather than guesses about missing stats.

Predictions & Output Format

The model generates predictions for tournament matchups in a human-readable format. For each game, it outputs:

Prediction Format:
  • Team Names: Team A and Team B in the matchup
  • Predicted Winner: The team with the higher win probability
  • Win Probability: Confidence level (e.g., Duke 72.5% vs UConn 27.5%)

For example, if the model predicts Duke has a 72.5% chance to beat UConn, the output shows: "Duke (72.5%)". These calibrated probabilities allow tournament participants to distinguish between close matchups (51% vs 49%) and mismatches (85% vs 15%), enabling smarter bracket-building decisions.

All predictions are saved to CSV format for easy tracking and accuracy measurement as the tournament progresses. This allows season-end analysis of which teams the model correctly identified and which predictions fell short.

Key Takeaways

This project demonstrates several important machine learning principles:

  • Feature engineering matters more than model complexity: Difference features capture matchup dynamics better than raw statistics.
  • Data preprocessing is critical: Handling name inconsistencies and missing values directly impacts prediction quality.
  • Probability estimates are more useful than binary predictions: Knowing a team is 65% likely to win is more actionable than just picking a winner.
  • Pipeline architecture ensures consistency: Applying the same scaling and model to new data guarantees reliable predictions throughout the tournament.
